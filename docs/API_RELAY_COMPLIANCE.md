# API 中继服务：安全边界与运营指引

本文说明 JCC Factory 可选 **API relay** 的技术和运营边界。API 中继 **not a VPN**：它只转发本应用发往 Gemini API 的请求，不提供通用网络接入、匿名化、区域解锁或监管规避能力。本文是运营指引，**不是法律意见**，也不保证任何部署满足法律、许可或合同要求。

启用前，管理员必须确认所用中继由本组织自建并授权，或由有权提供该服务的第三方明确授权。管理员还必须确认请求数据将经过中继，中继运营者与 Gemini 提供商都可能处理请求内容及相关元数据。

## 不变的责任边界

- **regional availability**：中继不会改变 Gemini 服务、模型、账号或项目的可用地区。以提供商当前公布的地区清单和账号控制为准。
- **provider terms**：中继不能规避服务条款、使用政策、内容安全、配额、计费、许可或账号限制。应用运营者仍对账号、调用和最终用途负责。
- **privacy**：中继增加了一个数据处理环节。运营者应识别提示词、视频/文档内容、用户输入、响应、标识符、日志和诊断元数据中的个人信息、敏感信息与机密信息。
- 不得把“请求技术上可到达”解释为“地区可用”“用途获准”或“满足当地法律”。中继和提供商返回成功也不是法律合规证明。

## 部署模式的区别

运营评审必须明确区分内部自建、授权第三方、公开转售、地区或安全规避，以及跨境数据处理；这些模式不能相互类推。

### 1. 内部自建、已授权中继

仅供同一组织的受控业务使用，通常最容易限定账号、调用方、日志、保留期和访问权限。仍须明确服务负责人、数据位置、TLS、密钥轮换、最小权限、日志脱敏、故障处置、删除与审计责任。内部使用不自动排除提供商条款、数据保护或跨境义务。

### 2. 已授权的第三方中继

第三方必须有权提供相应服务，并通过合同明确处理目的、数据类别、存储位置、保留与删除、分包方、事件通知、审计、终止和数据返还。不得仅凭其营销材料认定其获得 Google 授权、覆盖某地区或承担全部合规责任；应独立核实授权链和实际数据流。

### 3. 面向公众或客户的转售

把中继作为公共服务、共享账号能力或商业转售，与内部技术转发不是同一运营边界。它可能涉及提供商对转售、账号共享、品牌、支持和允许用途的限制，也可能触发电信、数据、消费者保护、生成式 AI 服务或其他许可与备案问题。公开或商业部署前，应取得适用法域的当地律师或法律顾问意见，并由业务负责人书面批准。

### 4. 地区或安全规避

不得使用本功能绕过 Gemini 的地区可用性、内容安全、禁止用途、配额、计费、风控、账号限制或其他服务条款。不得将它宣传为翻墙、VPN、区域解锁或匿名工具。发现中继用于上述用途时，应停用、保留不含秘密的审计证据，并按组织的安全与事件流程处理。

### 5. 跨境数据处理

如果中继、其分包方或模型提供商位于数据来源法域之外，请把整条路径视为潜在跨境数据流：浏览器/应用 → 中继 → Gemini → 中继 → 应用。上线前至少完成：

1. 列出数据类别、数据主体、发送目的、接收方、处理地点、分包方、保留期和删除路径；默认不发送完成任务所不需要的数据。
2. 对个人信息、敏感个人信息、重要数据、商业秘密和受合同限制的数据分别确定允许、禁止或需批准的处理规则。
3. 评估告知/同意、处理依据、个人权利、影响评估、安全措施、跨境机制、记录和事件响应要求；不要把中继位置当作唯一的数据位置。
4. 让安全、隐私、采购和法律负责人审查真实合同与真实数据流；法规阈值、豁免和程序可能变化，应在部署时复核官方现行文本。

## 应用技术约束

- 数据库键保持为 `proxy_service_enabled`、`proxy_service_url` 和 `proxy_service_auth_token`，通用配置更新接口只允许这三项。
- 中继 URL 必须使用 HTTPS；只有本机开发的 `localhost`、`127.0.0.1` 或 `::1` 可以使用 HTTP。URL 不得嵌入用户名或密码。
- 认证 token 最长 4096 个字符，不得含控制字符，也不得提交界面掩码值。token 不进入 URL、读取响应或日志；界面只显示已配置/未配置状态，替换时必须重新输入。
- 当前实现通过受控管理员界面/API 将中继 URL 和 token 持久化到数据库 `system_config`；它不支持从环境变量或秘密管理系统直接注入中继 token。部署必须通过受控 HTTPS 管理路径安全写入持久化配置；若组织要求秘密管理动态注入，须先另行实现、测试并维护受支持的集成，不能把 Gemini 环境变量机制推定为中继集成。
- 应用没有为 `system_config` 中的 token 提供字段级静态加密（encryption at rest）。限制数据库账户和管理员权限，保护数据库文件、卷、复制链路、备份与转储（dump），对介质启用适用的静态加密，并把恢复、导出和运维访问纳入秘密审计与轮换范围。
- 启用时服务端会重新验证已保存的 URL 和 token；启用后 URL/token 不可修改或清空，轮换必须先停用、替换，再重新确认启用。运行时发现已启用配置缺失、无效或不可读时会失败关闭，不会改走直连 Gemini。管理员界面还会要求显式确认授权、数据传输和禁止规避的边界。
- 中继端应验证调用方、限制目标上游、设置超时和请求大小、使用最小化日志、实施速率/成本限制，并拒绝把用户输入拼接成任意上游 URL。

## 启用前检查

- [ ] 中继所有者、授权范围和支持联系人已有书面记录。
- [ ] 真实部署使用 HTTPS；证书、域名和上游目标已验证。
- [ ] 已绘制真实数据流并完成数据最小化、保留、删除、访问控制和事件响应评审。
- [ ] 已核对当前地区清单、提供商条款、使用政策、Google APIs Terms、账号权限、配额和计费。
- [ ] 涉及第三方时，已核实分包方、处理地点、合同、安全措施和退出安排。
- [ ] 涉及公开、商业或跨境处理时，已完成适用法域的安全、隐私与当地法律顾问审查。
- [ ] 已测试禁用、token 轮换、连接失败、超时、限流、日志脱敏和撤销流程。
